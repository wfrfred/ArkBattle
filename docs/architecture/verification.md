# 已审查范围的语义验收

先确定需要保障的语义，再选择最小的代表场景。本页是后续重定测试的依据，不按现有测试反推需求，也不为每个接口、字段或内部步骤建立用例。

## 范围

- `core/battlefield/`：地图与地块、Unit 存储、结构占格、Navigation 和 Spatial 查询。
- `core/unit/` 的基础 Unit、构造、查询、Change，以及独立的 Action、Skill、Effect、Contribution 领域。
- `core/unit/capability/` 已审查到 Deployable：Action、Allegiance、Blocking、Deployable。
- 对应的 `core/battle/unit.ts`、Tile、Blocking、Deployment／Card、Occupancy 协作，以及调度器对上述领域的调用。
- 公共 Hook、Typed Ref 和 Lifetime 只承担上述领域共享的契约，不按每个消费者重复展开。

Deployable 对 Occupancy 的构造依赖、入场与配对属于本轮协作边界。Skill Capability 作为 Skill 领域的宿主接入，保留已确认的配对与资源职责。其余 Capability、完整 Projectile／Mechanism／Schedule 领域和 Legacy 展示协议不在本轮重新定测试的范围；被依赖不表示整域已经重新审查。

## 保留依据

领域文档的“关键语义”说明需要保障的结果；接口与实现章节供接入和维护参考，不自动转化为测试要求。尚未接入的机制、调查方向和设计示例不是已完成产品的验收承诺。

重要语义包括实际游戏结果、身份与资源不变量，以及会决定这些结果的跨领域结算边界。没有业务影响的遍历细序、对象复用、缓存结构和一 Tick 左右的局部轨迹差异，依照[项目语义尺度](README.md)取舍。

文档发生冲突时，先依据已确认的约定和机制证据统一文档。源码用于核对实现与缺口，既有测试不能裁定哪段历史描述应继续成立。

纯算法可以直接使用合法值，不要求每次计算都重放整场战斗。涉及运行身份、资源账务或生命周期的场景，通过所属领域操作建立事实；合成数据不得替代这些操作而伪造其已完成的结果。

## 必须保障的结果

下列条目是验收义务，不指定测试文件数或 `test()` 数量。一个真实场景可以同时覆盖多项；同一共享协议只保留集中保障，各领域仅补充不同的业务后果。

| 领域 | 关键结果 | 契约来源 |
| --- | --- | --- |
| Battlefield 版本与结构 | 写回不改写旧版本；全批最终布局决定同格双槽的唯一归属；结构发布不代办业务回调。 | [Battlefield](battlefield.md#关键语义) |
| 地图、导航与空间查询 | Tile 与 Overlay 决定当前可达性和导航结果；缓存不改变结果。身体位置、空间存在、占格和命中几何分别表达，空间接触不等于业务命中。 | [Battlefield](battlefield.md#关键语义)、[Spatial](spatial.md) |
| Unit 构造与能力 | 静态 Definition 决定能力组成，构造后配置与状态配对、组成稳定；初始 Effect 通过登记后的正常安装形成。 | [构造与装配](capability.md#初始化与装配) |
| Unit 批量变更 | 同目标的变换顺序接续，全部最终字段先发布，再执行各自的业务后继；嵌套结算不丢失已完成事实。 | [批量变更](api-conventions.md#51-unit-完整操作与批量变更) |
| 状态接续与 Hook | 同步业务接续最新状态；有意采样的历史事实保留。一次派发不吸收后来新增的候选，执行时使用最新登记与资格，嵌套派发独立。 | [状态接续](functional-core.md#状态接续后的读取与续执行)、[同步候选](functional-core.md#7-同步候选范围) |
| 身份与结束 | 持久对象与本轮执行身份不同，旧轮次不操作新轮次；结束立即拒收新的依赖，依赖者完整结束后宿主才注销，收尾不重复执行或覆盖首次原因。 | [Lifetime](lifetime.md)、[Action](action.md#关键语义)、[Skill](skill.md#关键语义) |
| Action | 启动受理、冷却、释放和输出保持各自含义；普通拒绝不创建执行。变速保留规定进度，释放前中断不伪造成功释放；已完成的输出与资源结算不回滚。 | [Action](action.md#关键语义) |
| Skill 与资源 | 持久状态与本轮状态分离；SP 门槛、实际支付、回复许可分开；TIME 延时只影响当前轮次，Ammo 使用自身公式、额度和耗尽政策。 | [Skill](skill.md#关键语义) |
| Effect 生命周期 | 安装、生效、禁用与结束产生正确输出；禁用保留实例与私有进度，结束撤销输出；生命周期依赖与来源信息分开。 | [Effect](effect.md#关键语义) |
| Effect 竞争与时间 | 覆写组赢家及禁用政策正确；绝对期限与周期进度分开，暂停不积攒补发，正常到期与内容续期按当前事实完成。 | [Effect](effect.md#关键语义) |
| Contribution 与阵营 | 互斥选择先于动态求值，修正采用所属领域公式；阵营不隐式决定其它能力或关系资格。 | [属性与贡献](capability.md#属性与贡献)、[Allegiance](capability.md#allegiance) |
| Blocking 资格与容量 | 双方资格、阻挡层、当前容量与体积决定取得；容量减少从后建立的关系开始裁撤，临时 HP 为零不提前解除可获救的关系。 | [Blocking](blocking.md#关键语义) |
| Blocking 关系与站位 | 批量解除先发布双端结果再通知；旧 Ref 不清掉新关系；普通关系解除与位置计划各有生命周期，主动脱离和空间覆盖完成自身清理。 | [Blocking](blocking.md#关键语义) |
| 部署受理与消费 | 查询和执行使用完整 Request 与一致资源事实；拒绝不消费，通过后先消费再构造、登记、入场；预览不创建实例或发布消费。 | [Deployment](deployment.md#关键语义) |
| Card 与经济 | Card 跨场上实例存续；库存、部署间隔和逐份恢复分别结算，启动时采样预算，暂停与减时不篡改其它段。DP 自然回复与主动增减分开。 | [Deployment](deployment.md#关键语义) |
| 撤退、死亡与占格配对 | 主动撤退先结算退款和 Card，再请求离场；死亡响应确认后的死亡事实。资源、占格与旧业务配对各自清理，不影响替代实例的新关系。 | [Deployment](deployment.md#主动操作与被动死亡)、[Occupancy](occupancy.md#关键协作语义) |
| 确定性与信任边界 | 相同输入、种子和程序得到相同重要结果；合法构造之后内部信任身份、能力与私有数据配对。复杂类型边界由少量编译期代表证明，不以运行时形状校验替代。 | [总体目标](ARCHITECTURE.md#范围与行为依据)、[构造与校验](capability.md#构造校验与命名) |

## 不单独保留的内容

- 每个 Getter／Setter 的字段形状、空数组、同引用、对象共享和重复缺失对象检查。
- 按领域、阶段、回调复制相同的 Hook、查询或生命周期矩阵。
- 旧 API 必须继续不存在、文件导出布局、Map／Hash／缓存键等实现形式。
- 绕过构造入口伪造内部身份、进度或关系，再要求内部防御；按游戏尺度不可达的溢出与非法调度。
- 夹具自写 Aura、Buff 应用或其它未接入的产品程序，再测试夹具自身的算法。

测试场景从上述结果与真实机制推导。夹具只准备这些场景需要的合法事实，不提供平行的能力装配、状态注入或领域结算协议。现有未提交测试改动也须重新按本页判断，不能因已修改而自动保留。
