# 已审查范围的语义验收

先确定需要保障的语义，再选择最小的代表场景。本页定义验收依据，不按现有测试反推需求，也不为每个接口、字段或内部步骤建立用例。代表场景的测试归属见[测试说明](../../test/README.md#已审查范围)。

## 范围

- `core/battlefield/`：地图与地块、Unit 存储、结构占格、Navigation 和 Spatial 查询。
- `core/unit/` 的基础 Unit、构造、查询、Change，以及独立的 Action、Skill、Effect、Contribution 领域。
- `core/unit/capability/` 已审查到 Deployable：Action、Allegiance、Blocking、Deployable。
- 对应的 `core/battle/unit.ts`、Tile、Blocking、Deployment／Card、Occupancy 协作，以及调度器对上述领域的调用。
- Unit 本地类型化 Hooks、HP／EP 的 Damage／Healing 两阶段结算，以及 Vitality／Elemental 的专属接收、资源提交与 Burst 协作。
- 公共 Hook、Typed Ref 和 Lifetime 只承担上述领域共享的契约，不按每个消费者重复展开。

Deployable 对 Occupancy 的构造依赖、入场与配对属于本轮协作边界。Skill Capability 作为 Skill 领域的宿主接入，保留已确认的配对与资源职责。其余 Capability、完整 Projectile／Mechanism／Schedule 领域和 Legacy 展示协议不在本轮重新定测试的范围；被依赖不表示整域已经重新审查。

## 保留依据

领域文档的“关键语义”说明需要保障的结果；接口与实现章节供接入和维护参考，不自动转化为测试要求。尚未接入的机制、调查方向和设计示例不是已完成产品的验收承诺。

重要语义包括实际游戏结果、身份与资源不变量，以及会决定这些结果的跨领域结算边界。没有业务影响的遍历细序、对象复用、缓存结构和一 Tick 左右的局部轨迹差异，依照[项目语义尺度](README.md)取舍。

文档发生冲突时，先依据已确认的约定和机制证据统一文档。源码用于核对实现与缺口，既有测试不能裁定哪段历史描述应继续成立。

纯算法可以直接使用合法值，不要求每次计算都重放整场战斗。涉及运行身份、资源账务或生命周期的场景，通过所属领域操作建立事实；合成数据不得替代这些操作而伪造其已完成的结果。

## 必须保障的结果

下列条目是验收义务，不指定测试文件数或 `test()` 数量。一个真实场景可以同时覆盖多项；同一共享协议只保留集中保障，各领域仅补充不同的业务后果。

| 领域 | 关键结果 | 契约来源 |
| --- | --- | --- |
| Battlefield 版本与结构 | 写回不改写旧版本；全批最终布局决定同格双槽的唯一归属；结构发布不代办业务回调。 | [Battlefield](battlefield.md#关键语义) |
| 地图、导航与空间查询 | Tile 与 Overlay 决定当前可达性和导航结果；缓存不改变结果。身体位置、空间存在、占格和命中几何分别表达，空间接触不等于业务命中。 | [Battlefield](battlefield.md#关键语义)、[Spatial](spatial.md) |
| Unit 构造与能力 | 静态 Definition 决定能力组成，构造后配置与状态配对、组成稳定；初始 Effect 通过登记后的正常安装形成。 | [构造与装配](capability.md#初始化与装配) |
| Unit 批量变更 | 同目标的变换顺序接续，全部最终字段先发布，再执行各自的业务后继；嵌套结算不丢失已完成事实。 | [批量变更](api-conventions.md#51-unit-完整操作与批量变更) |
| 普通注册 Change | Capability 用扁平 Rules／Contributions／Hooks 分组明确选择自动字段；按 Key 和固定字段两种接口均保持字段、Entry 与宿主 Ref 的类型关联，注册遵守按 ID 替换保序和无变化不结算。特殊字段由领域完成自身变换与后继。 | [批量变更](api-conventions.md#51-unit-完整操作与批量变更) |
| 状态接续与 Hook | 同步业务接续最新状态；有意采样的历史事实保留。一次派发不吸收后来新增的候选，执行时使用最新登记与资格，嵌套派发独立。 | [状态接续](functional-core.md#状态接续后的读取与续执行)、[同步候选](functional-core.md#7-同步候选范围) |
| 身份与结束 | 持久对象与本轮执行身份不同，旧轮次不操作新轮次；结束立即拒收新的依赖，依赖者完整结束后宿主才注销，收尾不重复执行或覆盖首次原因。 | [Lifetime](lifetime.md)、[Action](action.md#关键语义)、[Skill](skill.md#关键语义) |
| Action | 启动受理、冷却、释放和输出保持各自含义；普通拒绝不创建执行。变速保留规定进度，释放前中断不伪造成功释放；已完成的输出与资源结算不回滚。 | [Action](action.md#关键语义) |
| Skill 与资源 | 持久状态与本轮状态分离；SP 门槛、实际支付、回复许可分开；TIME 延时只影响当前轮次，Ammo 使用自身公式、额度和耗尽政策。 | [Skill](skill.md#关键语义) |
| Effect 生命周期 | 安装、生效、禁用与结束产生正确输出；禁用保留实例与私有进度，结束撤销输出；生命周期依赖与来源信息分开。 | [Effect](effect.md#关键语义) |
| Effect 竞争与时间 | 覆写组赢家及禁用政策正确；绝对期限与周期进度分开，暂停不积攒补发，正常到期与内容续期按当前事实完成。 | [Effect](effect.md#关键语义) |
| Contribution 与阵营 | 互斥选择先于动态求值，修正采用所属领域公式；阵营不隐式决定其它能力或关系资格。 | [属性与贡献](capability.md#属性与贡献)、[Allegiance](capability.md#allegiance) |
| 数值求值 | 动态属性接收同一 BattleState 中已取得的能力对象，贡献求值返回确定数值；对象缺失与采样时点由业务入口决定。Action 时序明确区分宿主 source 与具体 Action self，基础值取 self.definition。局部公式使用显式配置与状态，不自行回查宿主。 | [数值接口](api-conventions.md#5-数值输入查询与字段写回) |
| Blocking 资格与容量 | 双方资格、阻挡层、当前容量与体积决定取得；容量减少从后建立的关系开始裁撤，HP Applied 响应结束并确认死亡前保留旧关系。 | [Blocking](blocking.md#关键语义) |
| Blocking 关系与站位 | 批量解除先发布双端结果再通知；旧 Ref 不清掉新关系；普通关系解除与位置计划各有生命周期，主动脱离和空间覆盖完成自身清理。 | [Blocking](blocking.md#关键语义) |
| 部署受理与消费 | 查询和执行使用完整 Request 与一致资源事实；拒绝不消费，通过后先消费再构造、登记、入场；预览不创建实例或发布消费。 | [Deployment](deployment.md#关键语义) |
| Card 与经济 | Card 跨场上实例存续；库存、部署间隔和逐份恢复分别结算，启动时采样预算，暂停与减时不篡改其它段。DP 自然回复与主动增减分开。 | [Deployment](deployment.md#关键语义) |
| 撤退、死亡与占格配对 | 主动撤退先结算退款和 Card，再请求离场；死亡响应确认后的死亡事实。依赖者先结束，Unit 注销、结构占格与部署额度释放先于本地内容 leave；死亡 Card 先于 Card／Request 通知结算，旧业务配对清理不影响替代实例的新关系。 | [Deployment](deployment.md#主动操作与被动死亡)、[Occupancy](occupancy.md#关键协作语义) |
| 确定性与信任边界 | 相同输入、种子和程序得到相同重要结果；合法构造之后内部信任身份、能力与私有数据配对。复杂类型边界由少量编译期代表证明，不以运行时形状校验替代。 | [总体目标](ARCHITECTURE.md#范围与行为依据)、[构造与校验](capability.md#构造校验与命名) |

## 集中归属与收敛完成条件

已审查范围按下表集中保障。综合测试只保留新增的跨领域业务结果，不再重复所属领域的公式、输入矩阵、Setter、生命周期或 Hook 协议。文件位于 Content／Legacy 或同时涉及尚未审查领域，不构成重复测试的保留理由。

| 语义 | 集中归属与最小代表 |
| --- | --- |
| Unit 构造、能力配对和生命周期程序 | Unit：合法构造与一次真实生命周期。Hook 候选细则归 Hook，依赖析构细则归 Lifetime。 |
| 批量变更与同步状态接续 | Unit Change：一次跨字段批量提交与嵌套后继。各消费者只验证不同的业务后果。 |
| Hook 派发 | Hook：一次登记变化与嵌套派发，集中保障固定候选和最新登记。 |
| Runtime 组合 | 集中验证完整初始化／出生账簿先于 enter、一次正常预置替换保留最新绑定，以及 Tick 的阶段顺序／不可变发布与失败不发布。以公开创建、部署、资源和离场操作构造，不另写 marker、身份进度或内部存储夹具。 |
| HP／EP 接收与死亡 | 伤害／治疗回归清单。死亡确认前保留 Blocking 只归 HP-03，不在 Blocking／Combat 再做同构场景。 |
| 阻挡及位置计划 | Blocking：资格与层、容量尾部裁撤、批量通知与旧身份、独立位置计划。主动空间覆盖取消计划并解除旧关系，首个通知可见新位置，集中到位置计划场景。 |
| Card、部署、离场与占格 | Deployment：Request 与资源消费、主动／被动离场账务、一次旧占格配对不清理继任者、逐份恢复预算和 DP。删除旧 Battle 中相同构造与重入矩阵。 |
| Action、Skill、Effect 与 Contribution | 各自主套件。共有身份、候选、输入校验和不可变版本由公共套件承担，不因更换内容宿主再测一遍。 |
| 公共容器、Query 与类型关系 | 公共套件集中验证有序不可变写入、独立可重复遍历和必要的类型推断。删除逐方法空值／同引用／存储形状与极端数值矩阵。 |
| 普通注册工厂 | core-types 集中证明自动字段、Entry 与能力 Ref 的关联，包含不同 Hook 载荷及联合 Key 的代表。运行行为复用已有 Contribution、Hook、Unit Change 与伤害／治疗场景，不为每个 Capability、字段或生成函数新增测试。MaxHP 比例、Ammo 发动采样、Action 冷却和 Blocking 容量后继继续归各自主场景。 |
| 属性求值边界 | Contribution 主场景验证动态输入取得本次 Battle 和宿主，core-types 集中证明能力对象和可空 SP 的类型边界；多目标间重新采样、弹体来源离场缓存继续归实际攻击／弹体场景，不按属性重复建立缺失矩阵。 |
| 几何与空间算法 | 几何套件验证接触、范围旋转、坐标转换和扫掠的独立公式；Battlefield 验证当前地图、结构与查询协作。输入校验只留真正边界的代表，不在 Unit 等多层重复。 |
| UI 输出与具体内容 | Event 清单；内容只保留真实角色、装置或原生数据的独立结果，不自写护盾、Aura 等算法来重复证明公共结算。 |

收敛完成要求是：已审查语义有明确且集中的测试归属，旧套件中的相同覆盖已移除，仍必要的独立结果已归回其领域，失去用途的夹具和导入已删除。仅写出清单或新增主套件不算完成。

尚未完整审查的 Schedule／Data 解析、Route 执行、Locomotion／Targeting、完整 Projectile／Mechanism 等独立业务按现有范围保留；这些套件中夹带的上述已审查语义仍须去重，不能整文件豁免。测试数量是整理结果，不作为删减目标。

## Hook 与伤害／治疗的回归语义

以下清单先于本轮伤害／治疗测试编写，依据 [Hook 契约](hook.md)、[输出与接收](vitality.md#1-calculate-与-apply-的语义边界)、[资源提交](vitality.md#18-已定稿的接收与资源提交接口)和 [Elemental](elemental.md)确定。场景数量不随接口、阶段或历史故障增加；不得以现有测试的预期反推保留要求。

| 编号 | 必须保障的业务结果 | 定向场景 |
| --- | --- | --- |
| HOOK-01 | Unit 可以携带不同领域的精确 Hook，固有登记在首次 enter 前就绪；生命周期动态修改遵守固定候选、最新登记，leave 使用注销前最新程序及原 Departure。 | 公共集合／类型与一个实际 Unit 生命周期场景集中验证，不在四条管线重复候选矩阵。 |
| HP-01 | 物理、法术、真实及元素 HP 伤害采用各自公式；公式后类型与防御采样传到 Apply，初始 Request 不变。Calculate 不构成受击，也不写入本笔 HP。 | 合法基础属性与 Formula／Output 干预，核对最终数额、类型和接收前 HP。 |
| HP-02 | 从同一输入分别执行 Calculate 时，各自业务状态独立，调用方接续其中一个结果后只发生该次 Apply。弱点选高分支仍是具体内容待接入的规则。 | 当前只验证真实 Calculate／Apply 的独立分支和状态接续；不在夹具手写“选高”算法来证明产品已支持弱点。 |
| APPLY-01 | BeforeReceive 可改变准入；Receiving 的取消保留已完成业务并继续独立响应，取消后不提交。BeforeCommit 位于接收后与写入前，返回后使用最新资格及资源。 | 以真实无敌 Effect 与 Skill 的 HIT 回复接入、嵌套恢复等操作组合，核对准入先于受击回复、最终资源和固定提交报告；Hook 通用排序不再逐层重复。 |
| APPLY-02 | 四种业务均拒绝零计算输出；正数输出被接收为零或实际变化为零仍可成功。来源无 Vitality 仍可执行输出 Hook；同源同目标的两个 Applied 角色分别执行。 | 以最小合法 Unit 组合验证共同边界；治疗使用满资源，损伤使用完整吸收。 |
| HP-03 | HP 写入后先执行两侧 Applied，再按最新 HP 确认死亡，随后清理关系和注销。普通 Healing 不恢复零 HP；特殊生命干预接口仍待具体机制设计。 | 真实致死场景观察两侧响应中的零 HP、仍在场及原关系，响应结束后才注销并释放；不伪造零 HP 回正或复制 Lifetime 的整套析构测试。 |
| HP-04 | MaxHP 修正的登记、替换与撤销按比例接续当前 HP，不构成普通治疗；正常资源保留小数。 | 从合法构造与真实损伤形成受损对象，再通过 Contribution Change 验证资源比例。不用伪造零 HP、回调排列或逐字段构造校验矩阵。 |
| EP-01 | EP 抗性在 Calculate 采样，Apply 使用实际元素类型和最新 EP；四型独立损伤，治疗对每型应用完整数额，HP 元素抗性与 EP 抗性分离。损伤比例、恢复资格和 UI 使用同一有效 MaxEP。 | 明确的公式转换／抗性贡献和多型损伤、恢复，核对逐型结果；在已有恢复场景改变 MaxEP 贡献，验证损伤比例与元素圈一致，不另建 Getter 或 UI 矩阵，不以伪造运行状态准备场景。 |
| EP-02 | EP 耗尽同步登记 Burst 与 owner，先创建事实通知、再损失通知、再仍有效的启动程序，最后执行 Battle Applied；同步取消不运行旧轮启动，原损失报告不被改写。 | 一个正常爆发与一个在创建事实中取消的代表场景，必要依赖通过真实 install／scope 建立。 |
| EP-03 | Burst 期间拒收损伤与治疗；动态速度只改变剩余预算，暂停不积攒补算；正常完成与取消重置 EP，绑定输出结束而独立输出保留；自然恢复保持小数且不触发普通治疗通知。 | 通过真实损伤、贡献、结束和时间推进准备资源状态，集中验证资源及预算后果，不检查内部身份递增与单项 Setter。 |

原生爆发的伤害、异常、SP 与累计周期输出属于具体 Content／Data 的验收，不在资源管线中再实现一份内容程序。保留代表性的实际内容结果，不能用一个测试夹具自写模拟算法来替代。

旧的独立阶段、历史零值政策、重复回调矩阵和纯字段测试不作为保留目标。新套件按以上清单重新组织；不通过兼容夹具恢复旧登记协议，也不以修改旧断言作为本轮测试设计方法。

## Event 的回归语义

依据 [UI 瞬时输出](event.md)先确定以下结果，再选择最小代表场景。事件名称与历史诊断条数不是其它领域的业务验收依据。

| 编号 | 必须保障的结果 | 定向场景 |
| --- | --- | --- |
| EVENT-01 | HP／EP 伤害与治疗输出本次实际变化，元素损伤与元素 HP 伤害明确区分；资源变化及同步业务不依赖 Event 消费。 | 真实 Calculate／Apply 组合并交给实际表现转换器，验证必要飘字与报告；不复制四套管线矩阵。 |
| EVENT-02 | 元素爆发保存发生位置，Unit 注销保存离场历史事实；同 Tick 移动或注销不使 UI 丢失这些瞬时表现。输出顺序遵循实际发生顺序。 | 真实 EP 耗尽触发爆发，随后通过正常领域操作改变宿主位置并离场，UI 仍能输出原位置特效和死亡表现。 |
| EVENT-03 | 路线完成数由业务结算直接累计，UI 事件的追加或过滤不改变计数、Schedule 或结束判定；新 Tick 清空旧输出而保留旧状态。 | 正常路线完成场景读取计数及漏怪表现；通过公开 appendEvents 证明表现输出没有统计副作用，不伪造内部路线或生命周期状态。 |

现有其它领域测试中的诊断 Event 断言应删除；实际业务结果使用所属操作的 Outcome／Application、State 或 Hook 观察。Projectile／Blocking 等领域不因删除输出而新增一套同构测试。

- 按领域、阶段、回调复制相同的 Hook、查询或生命周期矩阵。
- 旧 API 必须继续不存在、文件导出布局、Map／Hash／缓存键等实现形式。
- 绕过构造入口伪造内部身份、进度或关系，再要求内部防御；按游戏尺度不可达的溢出与非法调度。
- 夹具自写 Aura、Buff 应用或其它未接入的产品程序，再测试夹具自身的算法。

测试场景从上述结果与真实机制推导。夹具只准备这些场景需要的合法事实，不提供平行的能力装配、状态注入或领域结算协议。回归问题若属于已有语义，应修正或扩充其代表场景；只有独立的重要结果才需要新场景。
