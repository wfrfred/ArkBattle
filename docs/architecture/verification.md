# 已审查范围的语义验收

先确定需要保障的语义，再选择最小的代表场景。本页定义验收依据，不按现有测试反推需求，也不为每个接口、字段或内部步骤建立用例。代表场景的测试归属见[测试说明](../../test/README.md#已审查范围)。

## 范围

- `core/battlefield/`：地图与地块、Unit 存储、结构占格、Navigation 和 Spatial 查询。
- `core/unit/` 的基础 Unit、构造、查询、Change，以及独立的 Action、Skill、Effect、Contribution 领域。
- `core/unit/capability/` 已审查 Action、Allegiance、Blocking、Deployable、Hitbox、Layer、Locomotion 与 Presence。
- 对应的 `core/battle/unit.ts`、Tile、Blocking、Deployment／Card、Occupancy 协作，以及调度器对上述领域的调用。
- Unit 本地类型化 Hooks、HP／EP 的 Damage／Healing 两阶段结算，以及 Vitality／Elemental 的专属接收、资源提交与 Burst 协作。
- 公共 Hook、Typed Ref 和 Lifetime 只承担上述领域共享的契约，不按每个消费者重复展开。

Deployable 对 Occupancy 的构造依赖、入场与配对属于本轮协作边界。Skill Capability 作为 Skill 领域的宿主接入，保留已确认的配对与资源职责。其余 Capability、完整 Projectile／Mechanism／Schedule 领域和 Legacy 展示协议不在本轮重新定测试的范围；被依赖不表示整域已经重新审查。

## 保留依据

领域文档的“关键语义”说明需要保障的结果；接口与实现章节供接入和维护参考，不自动转化为测试要求。尚未接入的机制、调查方向和设计示例不是已完成产品的验收承诺。

重要语义包括实际游戏结果、身份与资源不变量，以及会决定这些结果的跨领域结算边界。没有业务影响的遍历细序、对象复用、缓存结构和一 Tick 左右的局部轨迹差异，依照[项目语义尺度](README.md)取舍。

文档发生冲突时，先依据已确认的约定和机制证据统一文档。源码用于核对实现与缺口，既有测试不能裁定哪段历史描述应继续成立。

纯算法可以直接使用合法值，不要求每次计算都重放整场战斗。涉及运行身份、资源账务或生命周期的场景，通过所属领域操作建立事实；合成数据不得替代这些操作而伪造其已完成的结果。

## 集中归属与收敛完成条件

已审查范围按下表集中保障。综合测试只保留新增的跨领域业务结果，不再重复所属领域的公式、输入矩阵、Setter、生命周期或 Hook 协议。文件位于 Content／Legacy 或同时涉及尚未审查领域，不构成重复测试的保留理由。

| 语义 | 集中归属与最小代表 |
| --- | --- |
| Unit 构造、能力配对和生命周期程序 | Unit：合法构造与一次真实生命周期。Hook 候选细则归 Hook，依赖析构细则归 Lifetime。 |
| 组合变更与同步状态接续 | Unit Change 的一个主场景集中验证同目标 compose 的结合律与非交换、每项 previous／no-op／Settlement，以及最终 next 一次发布和嵌套后继。第二 Unit 通过 Settlement 中正常的 update 改变，不作为跨 Unit 批次；各消费者只验证不同的业务后果。 |
| Hook 派发 | Hook：一次登记变化与嵌套派发，集中保障固定候选和最新登记。 |
| Runtime 组合 | 集中验证完整初始化／出生账簿先于 enter、一次正常预置替换保留最新绑定，以及 Tick 的阶段顺序／不可变发布与失败不发布。以公开创建、部署、资源和离场操作构造，不另写 marker、身份进度或内部存储夹具。 |
| HP／EP 接收与死亡 | 伤害／治疗回归清单。死亡确认前保留 Blocking 只归 HP-03，不在 Blocking／Combat 再做同构场景。 |
| 阻挡及位置计划 | Blocking：资格与层、容量尾部裁撤、批量通知与旧身份、独立位置计划。自身空地设置的清理（含同值）复用批量解除与位置计划代表场景，通知读取已发布的新身份；主动空间覆盖取消计划并解除旧关系，首个通知可见新位置。不按字段、角色或切换方向另建矩阵。 |
| 空间存在及其协作 | Presence 集中验证保留身份、部署与 Occupancy、Effect／Lifetime，以及全部限制先于批量解除通知；合法通知中重新出现并启动的新执行不受旧捕获集合清理。Blocking 保留自身偏移与目标独立计划的区别；Action／Skill、资源接收、Burst 和 tracking 弹道只在各自主场景验证新增的业务结果，不复制 Rule 登记、Hook 或生命周期矩阵。 |
| 自主运动 | Locomotion：纯算法集中验证转向、直邻／斜邻避障及反射公式；真实移动场景验证当前速度、最终目标吸附和暂停后的历史速度。半身宽、WALK 高代价格／FLY 硬障碍、方向投影与速度比例、不可通格恢复各保留独立结果，不枚举八方向及微小数值变体。Route 集成只保留等待、当前导航方式与 Layer 分离、阻挡解除后路线完成等协作结果；历史速度通过实际推进建立，不直接注入 Unit。 |
| Card、部署、离场与占格 | Deployment：Request 与资源消费、主动／被动离场账务、一次旧占格配对不清理继任者、逐份恢复预算和 DP。删除旧 Battle 中相同构造与重入矩阵。 |
| Action、Skill、Effect 与 Contribution | 各自主套件。共有身份、候选、输入校验和不可变版本由公共套件承担，不因更换内容宿主再测一遍。 |
| 公共容器、Query 与类型关系 | 公共套件集中验证有序不可变写入、独立可重复遍历和必要的类型推断。删除逐方法空值／同引用／存储形状与极端数值矩阵。 |
| 普通注册工厂与变更类型 | core-types 集中证明自动字段、Entry 与能力要求的关联，包含不同 Hook 载荷及联合 Key 的代表。Change 的能力参数逆变，compose 合并两侧要求为交集；泛型 apply 保留输入完整宿主类型，update 拒绝能力不足的目标 Ref。运行行为复用已有 Contribution、Hook、Unit Change 与伤害／治疗场景，不为每个 Capability、字段或生成函数新增测试。MaxHP 比例、Ammo 发动采样、Action 冷却和 Blocking 容量后继继续归各自主场景。 |
| 属性求值边界 | Contribution 主场景验证动态输入取得本次 Battle 和宿主，core-types 集中证明能力对象和可空 SP 的类型边界；多目标间重新采样、弹体来源离场缓存继续归实际攻击／弹体场景，不按属性重复建立缺失矩阵。 |
| 几何与空间算法 | Coordinate 集中验证坐标转换与四向旋转；Range 用一次非默认朝向、连续原点与不连续并集验证组合。Geometry 保留圆、盒及混合圆角的独立相交／首次扫掠公式、局部偏移与必要接触边界，不按方向、尺寸或微小数值变体复制。输入校验只留真正边界的代表。Battlefield 验证位置与 Hitbox 的区别、空间资格和接触顺序，不重复精确交点或旧版本不可变性。 |
| UI 输出与具体内容 | Event 清单；内容只保留真实角色、装置或原生数据的独立结果，不自写护盾、Aura 等算法来重复证明公共结算。 |

Hitbox 的 Targeting 接入只保留一个代表场景：显式范围使用受击几何，无 Hitbox 的对象可以通过不含几何条件的选择，空地过滤读取当前 Layer 而非 Definition 初值或 Route。空间消失通过真实领域操作形成，不构造未发布的离场／零 HP 快照。按身份命中的真实锁定弹道另行保留，它有独立的命中语义；不在该场景重复 UI 条数或旧状态验证。具体 Content 不为传递几何字段或比较没有独立玩法结果的细小运动差异建立回归。

收敛完成要求是：已审查语义有明确且集中的测试归属，旧套件中的相同覆盖已移除，仍必要的独立结果已归回其领域，失去用途的夹具和导入已删除。仅写出清单或新增主套件不算完成。

尚未完整审查的 Schedule／Data 解析、Route 执行、Targeting、完整 Projectile／Mechanism 等独立业务按现有范围保留；这些套件中夹带的上述已审查语义仍须去重，不能整文件豁免。测试数量是整理结果，不作为删减目标。

## Presence 的回归语义

以下结果依据 [Presence 契约](presence.md)确定；场景通过正常构造、部署、阻挡取得、启动与资源结算建立事实。`appear(position)`／`disappear()` 返回要求 SpatialPresence 的 Change，由 `unit.update(battle, ref, change)` 提交；同目标变更通过二元 compose 组合，Presence 可以在组合中的任意位置，最终 Unit 先发布，不要求它排在首位。

| 必须保障的业务结果 | 集中归属 |
| --- | --- |
| 消失保留原 Unit、占格、部署额度及普通 Effect／Lifetime，不派发入场或离场；全部限制先发布，Presence 的解除通知可见整批双端解除。后继从本项 previous 固定旧关系与旧执行，不把较早 Settlement 的通知中新建的执行捕入清理。 | Presence 主场景；公共旧 Ref、Hook 候选和析构协议不重测。 |
| 自身 Blockable 偏移随主动空间覆盖取消；Blocker 消失只解除关系，原目标的独立偏移继续。已 present 的 appear 仍执行位置覆盖及自身清理。 | Blocking 原位置计划场景。 |
| 消失禁止新的 Action／Activation，取消旧 Action 并停止旧输出；已完成释放前缀保留。开始通知中消失但仍 ACTIVE 的同轮 Skill 执行 onStart，既有持续技能仍正常推进及到期。 | Action／Skill 原代表场景；不据此增加弹药消费政策。 |
| 消失期间普通 HP／EP Damage 拒收；明确目标的 HP／EP Healing 仍遵守各自条件。自然 EP 回复与已启动 Burst 的恢复预算继续，消失不取消其 Effect。 | 一次双资源接收场景及 Elemental 原恢复场景，不重复四条管线的公式与通知矩阵。 |
| 普通空间查询、Targeting 与 Terrain 排除消失对象；已锁定 tracking 弹道仍追现存目标的真实位置，身份命中与 Damage 接收分开。 | 原空间／目标／Terrain 场景与真实弩箭追踪场景，不新增 Projectile Rule 或每个消费者的隐藏版本。 |

## Hook 与伤害／治疗的回归语义

以下清单先于本轮伤害／治疗测试编写，依据 [Hook 契约](hook.md)、[输出与接收](vitality.md#1-calculate-与-apply-的语义边界)、[资源提交](vitality.md#18-已定稿的接收与资源提交接口)和 [Elemental](elemental.md)确定。场景数量不随接口、阶段或历史故障增加；不得以现有测试的预期反推保留要求。

| 编号 | 必须保障的业务结果 | 定向场景 |
| --- | --- | --- |

| HP-03 | HP 写入后先执行两侧 Applied，再按最新 HP 确认死亡，随后清理关系和注销。普通 Healing 不恢复零 HP；特殊生命干预接口仍待具体机制设计。 | 真实致死场景观察两侧响应中的零 HP、仍在场及原关系，响应结束后才注销并释放；不伪造零 HP 回正或复制 Lifetime 的整套析构测试。 |

| EP-03 | Burst 使用 rate 为零的 DURATION，在 onTick 按当前恢复速度手动推进同一份 expiration.elapsed；该进度决定恢复预算与周期边界，恢复期间四型 EP 按当前有效上限逐步回填，期间拒收损伤与治疗，动态速度与暂停不积攒补算。自然完成包含预算内最后一次周期输出，取消、提前结束与离场不补未来输出；结束先清依赖，再写满 EP、清槽并通知 burstEnded。零预算仍执行安装业务后结束，不补周期输出；永久减防、剩余麻痹和独立眩晕使用各自生命周期。自然恢复保持小数且不触发普通治疗通知。 | 通过真实损伤、贡献、结束和时间推进验证暂停、恢复中间值、完成／取消及作用生命周期；零预算只用实际标准效果验证一次性输出与独立产物，公共时间边界归 Effect。不检查内部身份递增或按每型配置逐字段展开。 |

标准爆发的伤害、异常、SP 与累计周期输出由 Core 的八个具体 Effect 执行，Data 选择对应实现并提供各自的数值参数。测试保留代表性的实际标准效果结果，不在夹具中重写爆发算法，也不为八套配置建立重复的字段或回调矩阵。

旧的独立阶段、历史零值政策、重复回调矩阵和纯字段测试不作为保留目标。新套件按以上清单重新组织；不通过兼容夹具恢复旧登记协议，也不以修改旧断言作为本轮测试设计方法。

## Event 的回归语义

依据 [UI 瞬时输出](event.md)先确定以下结果，再选择最小代表场景。事件名称与历史诊断条数不是其它领域的业务验收依据。

| 编号 | 必须保障的结果 | 定向场景 |
| --- | --- | --- |
| EVENT-01 | HP／EP 伤害与治疗输出本次实际变化，元素损伤与元素 HP 伤害明确区分；资源变化及同步业务不依赖 Event 消费。 | 真实 Calculate／Apply 组合并交给实际表现转换器，验证必要飘字与报告；不复制四套管线矩阵。 |
| EVENT-02 | 元素爆发保存发生位置，Unit 注销保存离场历史事实；同 Tick 移动或注销不使 UI 丢失这些瞬时表现。输出顺序遵循实际发生顺序。 | 真实 EP 耗尽触发爆发，随后通过正常领域操作改变宿主位置并离场，UI 仍能输出原位置特效和死亡表现。 |
| EVENT-03 | 路线完成数由业务结算直接累计，UI 事件的追加或过滤不改变计数、Schedule 或结束判定；新 Tick 清空旧输出而保留旧状态。 | 正常路线完成场景读取计数及漏怪表现；通过公开 appendEvents 证明表现输出没有统计副作用，不伪造内部路线或生命周期状态。 |

现有其它领域测试中的诊断 Event 断言应删除；实际业务结果使用所属操作的 Outcome／Application、State 或 Hook 观察。Projectile／Blocking 等领域不因删除输出而新增一套同构测试。

## 不单独保留的内容

- 每个 Getter／Setter 的字段形状、空数组、同引用、对象共享和重复缺失对象检查。
- 按领域、阶段、回调复制相同的 Hook、查询或生命周期矩阵。
- 旧 API 必须继续不存在、文件导出布局、Map／Hash／缓存键等实现形式。
- 绕过构造入口伪造内部身份、进度或关系，再要求内部防御；按游戏尺度不可达的溢出与非法调度。
- 夹具自写 Aura、Buff 应用或其它未接入的产品程序，再测试夹具自身的算法。

测试场景从上述结果与真实机制推导。夹具只准备这些场景需要的合法事实，不提供平行的能力装配、状态注入或领域结算协议。回归问题若属于已有语义，应修正或扩充其代表场景；只有独立的重要结果才需要新场景。
