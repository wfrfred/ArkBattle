# Tactical 目标语义与实现缺口

本文规定 Tactical 应表达的玩法语义，并记录尚未达到这些要求的地方。领域划分与纯状态契约见[总体架构](ARCHITECTURE.md)、[函数式内核](functional-core.md)；本文不以当前代码、测试或原生客户端的内部结构代替目标规则。

## 范围与依据

- 范围是主模式干员、敌人的通用作战机制，以及卫戍协议需要的模式接入。生息演算、保全派驻、船运寻路不在范围内；PRTS 列出的全部模式和特殊指令不自动成为本项目的实现清单。
- PRTS 的[仇恨](https://prts.wiki/w/仇恨)、[数值范围](https://prts.wiki/w/数值范围)、[异常效果](https://prts.wiki/w/异常效果)等页面注明适用版本。目标优先采用可观察的规则；精确常数、历史溢出和注明存疑的分支需核对版本，不直接固化为长期契约。

大语义遵从官方，小差异从简：显著改变目标、命中次数、技能状态、累计数值或胜负的差异应核对资料或客户端；中间顺序先说明实际观察它的业务；普通一个 Tick 左右的响应差异采用简单、确定的约定；纯工程中间过程不增加机制。固定 Tick、函数式状态传递、RNG 实现、缓存和文件组织属于项目选择。

用户明确选择的玩法差异以对应项目规则为准。弱点伤害允许两个候选各自执行带 Hook 的完整计算，接续较高结果的状态后实行一次；这有意区别于官方理论试算，不以恢复官方比较规则为修复目标。详见 [Vitality / Damage 设计](vitality.md#2-弱点伤害的项目规则)。

healFree 只限制治疗目标选择，明确 Ref 的 Healing 不重新检查选中限制，已选中后获得限制不撤销本次治疗。这个项目政策有意区别于官方 HEAL_FREE 同时影响选中和接收的组合；真正的治疗取消通过 Receiving Hook 表达。详见 [Healing 项目政策](vitality.md#41-治疗不可选中是项目选择)。

主表只保留尚未完成的机制与待核对问题。已完成的基础契约见对应领域文档；部分基础可用不代表内容、调用链及交互已经完整接入。测试预期应来自明确的玩法规则。

优先级是影响与依赖顺序，不是工时：**P0** 为基础战斗结果或完整链路的关键条件，**P1** 为常见机制和已确认结算缺陷，**P2** 为特定内容扩展或需要案例收敛的边界。缺失本身不等于需要新增 Capability。

## 子系统的目标职责

| 子系统 | 目标职责与边界 |
| --- | --- |
| Battle | 同步接续领域结果，保存执行进度，汇总事件和模式结果；完整 Tick 成功后发布状态。 |
| Battlefield | 保存不可变实体、空间与关系事实，维护存储及索引一致性；Blocking 的时序操作与同步通知由完整战斗操作结算。 |
| Unit / Capability | Unit 组合所需能力；能力提供自身的静态规则、运行状态、查询、局部更新与完整结算。 |
| Contribution | 带身份的不可变泛型候选；只管理登记、替换与互斥，载荷和归并由所属领域决定。 |
| Hook | 接入所属领域的明确阶段；领域决定顺序和本次裁决，具体内容接续返回状态。 |
| Effect | 保存宿主附着实例、私有数据、覆写与生命周期；具体 Definition 组合 Capability 操作。 |
| Targetable / Targeting | 前者承载固有与动态索敌限制贡献；后者按请求显式提供的 Filter 与 Selector 执行资格筛选、排序、数量选择及随机抽样。见 [类型设计](targeting.md)。 |
| Action / Skill | Action 保存行动过程；Skill 保存技力与激活进度。释放、耗弹、回复、结束分别在明确业务时点发生。 |
| Locomotion / Route / Navigation | 分别处理运动、行动脚本和可通行路径；行动类型、寻路方式、阻挡模式不互相代替。 |
| Projectile | 已发射后的独立过程，保存目标、样本、命中历史与飞行进度；内容决定接触和终止策略。 |
| Deployment / Card | Deployment 管费用与部署操作；Card 管跨实例的供给、费用惩罚和冷却；Deployable 管场上部署属性。 |
| Schedule / Predefined | 分别管理出兵／关卡动作进度，以及预置定义与运行实例的绑定。 |
| Data / Content | Data 适配原始配置；Content 实现具体角色、技能、天赋、装备和模式规则，组合领域操作。 |
| Meta / 模式规则 | 外层经营与回合生成战斗输入；本场即时规则显式接入 Tactical，结果与归属反馈回外层。 |

旧版 `server/match` 仍调用 `server/sim/Battle.js`；新内核由 `src/legacy` 接入演示。旧版已经有的经营、联防、领袖战不能算作新 Tactical 已经接入，也不能因新内核缺少它们就认定整个仓库没有这些功能。

## 待完成工作的补充说明

1. **RETURN 丢回收已复现。** 有限库存 2、活动上限 2，连续部署两次并在 Tick 1 / 2 返回，冷却 10 Tick；Tick 12 后 stock 为 1、cooldown 为 null、pendingReturns 为 0。目标是保存两个回收事实；可以约束单计时 RETURN 的合法组合，或实现所需多实例政策，不能把内部覆盖行为固化为游戏规则。
2. **方向和手动撤退资格是执行入口缺口。** 固定方向的内容工厂不等于可选择方向的部署；通用移除能力不等于手动撤退规则。它们需要领域契约，不需要 Core 再维护通用权限系统。
3. **攻击 SP 的基础入口不代表连击全覆盖。** 当前首次释放入口可用于普通攻击；每段伤害不自动等于一次攻击，必须用真实多次攻击和剑豪例外分别验证。
4. **不提供免费重定位代替术语移动。** 直接重定位部署对象的接口已删除；特殊撤退—再部署需要结束和重新进入、Buff / Skill 初态、HP 响应及失败后继，属于待接入的完整业务。
5. **低速攻速、回调微时序不先定为错误。** 当前基础 ASPD 下限 20 与间隔计算下限属于不同阶段；范围覆写是否使更低速度可达需另查。父子结束、满 SP 时的细微余量和单 Tick 响应也先证明实际影响。
6. **功能缺失与架构问题分开。** 五型元素、地形、复杂弹道、特殊异常和更多角色可以按代表内容扩展；是否需要新的状态或接入点由真实执行链路决定。

## 重点规则的验收案例

这些是从目标推导的验收要求，尚未全部建立测试。修复不能只更改旧断言而保留旧解释。

| 范围 | 必须验证的结果 |
| --- | --- |
| 普通索敌 | 敌人范围内 A 更近、B 后部署时按对应仇恨选择；我方范围内 A 更近、B 剩余路线更短时按路线仇恨选择；嘲讽与明确的特殊排序分别验证。 |
| 阻挡例外 | 被阻挡敌人可攻击隐匿阻挡者；我方阻挡仍有效隐匿敌人时不自动绕过隐匿；敌方解除隐匿后才可被相应能力选中。 |
| 迷彩 | 普通能力受限制；明确无视迷彩或采用对应中点／格子策略的能力可选；不能仅凭名字中含 AOE 判定例外。 |
| 沉默 | 可沉默能力暂停、解除后恢复；不可沉默技能可触发；无条件禁止能力使用静默等对应机制，不误标为沉默。 |
| 无敌与元素 | 有 EP 的单位启用无敌后，直接元素损伤不扣值；独立关闭一个无敌来源不撤销其他来源的保护；混合 HP / EP 行动分别结算。 |
| 元素免疫 | 阻止损失但可进行符合规则的恢复；爆发冷却单独阻止恢复；解除一种限制不解除另一种。此项先按 PRTS 定义验收，需跟进客户端复核。 |
| 弹药 | 剩余 1 发、要求消耗 2 发时记录指定消耗和负余量；最后一击与下一次普攻检查之间保持正确技能状态；手动关闭、特殊倾泻分别验证。 |
| 连击 SP | 普通多次攻击按内容逐次回复；剑豪特性例外只回复一次；释放被中断和单次攻击多目标不误增回复次数。 |
| 费用与方向 | 超过关卡上限的部署按上限裁定；同一 Card 的两次部署可选不同方向，并改变范围和方向相关业务。 |
| 特殊免费部署 | 实际扣账为 0，场上费用属性仍可为正常值；允许返费时按倍率／上限结算；特殊部署通知不冒充手动部署。 |
| 手动撤退 | 可手动撤退的实例正常退出；不可手动撤退的对象拒绝命令；内容强退仍能进入正确离场流程；外层控制范围单独验证。 |
| Card 回收 | 普通单实例 RETURN 不丢库存；合法多实例政策保存每次回收；被判非法的供给组合在构造边界明确拒绝。 |
| 术语移动 | 合法目标重新登场，按内容清理 Buff / Skill / SP 并处理生命比例；非法目标和返回标志物失效执行对应后继；不积累普通撤退惩罚。 |
| 地形与承载 | 地面进入地穴触发坠落；飞行及落地按规则重判；承载物消失的设施内容完成所需后继，而非只删关系。 |
| 模式结果 | 漏怪、计数、非首要目标和来源归属正确；卫戍倒下不等于普通死亡移除；领袖超时规则不由通用 maxTicks 截断代替。 |

### 仇恨事实与普通排序

嘲讽作为动态属性，角色的实际出场 Tick 与同 Tick 顺序作为当前出场实例的持久事实，敌人剩余路线由 Route／Navigation 提供只读查询。基础仇恨由 Comparator 计算，不在 Targetable 重复存储。角色类和敌人类是实体类别，不能通过当前阵营推断应使用哪一种公式。

采用固定出场顺序的项目政策；不复刻原生角色 UpdateHatred 缓存重新读取同帧全局计数的行为。出场事实在实际入场时确定，不能沿用 Definition 创建或预分配 ID 的顺序，重新部署应建立新事实。相关状态归属与查询接入尚未完成，现有内容的显式 distance 策略保持可见，不能当作普通仇恨已经实现。

## 推进顺序与完成标准

1. 修正普通索敌与目标资格：补目标侧事实、选择器策略和正确的阻挡／迷彩例外。
2. 完成特殊接收与状态组合：元素免疫的客户端复核、沉默／静默及特殊弹药内容。
3. 完成普通部署闭环：方向、实际费用上限、手动资格、Card 回收不变量；随后接入免费与术语移动。
4. 用代表内容核对 Action / Skill / SP，再接入动态属性、Buff 叠加、抵抗与 Aura。先把顺序语义写清楚，不先做批量优化。
5. 接入关卡结果与模式机制，再衔接旧 Meta；地形、特殊弹道、异常和元素扩展按实际内容依赖推进。

完成一项意味着：目标规则有可核对依据，实际调用链已接入，代表性正常与关键交互场景可验证，历史输入／快照保持不变，正常拒绝与失败 Tick 的边界正确。解析器分支、接口、模板、单个孤立测试或旧版实现的存在均不能单独作为完成证据。

缺口关闭后，将有效语义与回归要求保留在所属领域，移除完成状态汇报。新审查与当前记录冲突时先核对代码版本、能力适用范围及实际业务观察者，不按报告数量投票。
