# Tactical 目标语义与实现缺口

本页集中记录支持边界与未闭合机制；当前职责、时序和接口以各领域文档为权威，必要验收统一见 [Verification](verification.md)。现有代码、解析分支或测试通过均不能证明真实机制完整覆盖。

## 范围与依据

ArkBattle 面向通用明日方舟战斗，卫戍协议是实现重点，不是 Core 边界。生息演算、保全派驻等明确排除的特殊模式及船运寻路不在当前范围；不能据此排除普通主线的真实机制。

原生证据、实际内容使用、已确认项目选择与未知分支分别记录。显著影响目标、命中次数、资源、技能状态或战斗结果的差异须有依据；微小时间近似只能在已获准范围使用，不能替代调查或自动扩大为其他机制的简化。

[资源覆盖](../research/cases/37-resource-mechanism-coverage.md)、[单位分类](../research/cases/36-unit-classification-and-combat-tags.md)与各领域研究提供可追溯依据。弱点双分支计算、healFree 仅限选择、逐 Tick 自然回复等已批准差异见 [Resource](resource.md)，不在这里重复完整协议。

## 子系统职责

[总体架构](ARCHITECTURE.md)是领域分工权威。Data 转换静态输入并可绑定已有工厂，Content 提供具体程序，Core 初始化和推进运行 State；调用者裁决终局。领域可组合接口只是实现基础，不代替实际内容链。

Targeting 的查询抽象见[领域设计](targeting.md)，完整上下游依据见[原生索敌调查](../research/cases/33-targeting-and-targetable-pipeline.md)。

### 仇恨事实与普通排序

Targetable 提供有效嘲讽，UID 表达入场先后，Route／Navigation 提供剩余路程。内容选择比较政策，distance 不冒充普通仇恨，也不从阵营推导实体类别。

### 弩手锁定后的阵营检查

当前弩箭命中仅复验目标 PRESENT 与正生命，不重新检查阵营。是否需要在锁定后复验、使用哪个阶段的阵营事实仍依实际弹道核对；它与启动索敌是不同业务时点，不能由标准候选政策自动推导。
