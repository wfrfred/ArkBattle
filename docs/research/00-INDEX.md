## 本轮可以收敛的判断

`BattleRuntime → Battlefield → Unit + capabilities` 可以保留为状态组织的大框架。这个箭头表示组织与所有权，不要求所有领域模块只能沿箭头单向调用，也不意味着战场上的所有过程都必须是 Unit capability。

需要澄清的是下列边界：

- **Subsystem 按稳定领域规则划分。** 目标查询、伤害接收、阻挡、运动等有各自的输入、时序和不变量；各能力所属领域提供贡献操作与有效值查询，不另设统一 Attributes 状态或管理器。
- **内容程序负责组织具体机制。** 技能、天赋、投射物命中程序和 Buff 模板可以组合多个领域操作；伤害领域仍然负责公式、接收与生命转换。
- **Effect 目前混用了不同意思。** 一次操作、持续 Buff／标记、空间规则贡献需要分别讨论；它们不能因共用这个词就共享生命周期。
- **Hook 是领域流程里的明确介入点。** 各领域定义介入契约与排序，内容编译绑定行为，Buff core 管实例生命周期，执行上下文管理候选范围；不合并成全领域 BuffProgram 或广播总线。
- **Resources 是实现分类。** 编译程序、模板解析结果和派生缓存可以重建；层数、护盾余量、父子 Buff 关系、源与接收安装联系、弹药和在途执行进度都是运行事实。
- **权威事实只有唯一 owner。** 样本逐机制归属，跨领域结果明确为同步维护的投影；注册贡献可以是固定值、周期采样、状态变化更新或实时纯 provider。
- **参与与存在分别表达。** 停止参与不自动删除旧载荷，恢复政策由具体内容决定；派发冻结已登记候选身份，进入前重查资格。
- **正常领域拒绝／取消与 tick 中止分别处理。** 前者保留按协议完成的前缀，后者才使整个工作 fork 不发布。

两项具体证据对下一轮设计约束最大：官方 Buff 有父子结束传播及多种覆盖／续期规则，超出当前实例模型的有限支持；官方攻击存在施法阶段、弹道与命中动作，超出当前即时 DAMAGE／HEAL 行动。它们都不能靠增加几个伤害 hook 完整解决。

## 范围与证据纪律

范围是本项目需要模拟的卫戍协议战斗，以及其中干员、敌人、设备所依赖的常规机制。生息演算、保全派驻、船运寻路和已决定排除的 WORD 机制不纳入本轮。

目标是项目自身确定性与重要玩法语义一致。同一项目规则版本、初始状态、seed 和命令序列应产生一致结果；不要求与官方同 seed 的结果、RNG 调用轨迹或内部实现逐位一致。

官方帧率、对象更新顺序和一 tick 内的微时序允许近似。提前或延后一 tick 本身不构成缺陷；验收关心它是否改变重要的离散结算结果、形成可察觉的玩法／表现差异，或累积成显著数值偏差。官方的复杂或反常路径也可以简化，只要满足这项标准。固定 30 tick/s 和 `Combat → Projectile → Movement` 是已接受的项目政策，无须复制官方对象 UID 队列。

重复／漏失命中、重要目标选择、触发次数、状态传播和胜负等结果仍需按具体机制验证；持续攻速、周期伤害等还要检查累计数值。少见边界或内部顺序不同不自动意味着重要玩法差异，接受近似也不意味着已经证明所有场景严格等价。

随机机制需要保留概率、候选与选择规则、条件依赖，以及具有玩法含义的重复／关联。未产生语义影响的抽样可以省略，纯条件检查可以提前，概率 0／1 不需要复刻官方是否消费 RNG。仅因改变消费顺序使后续伪随机序列不同，不构成官方兼容问题。

研究官方微时序需要说明具体影响及其重要性，不能仅因目标、伤害、状态或位置的发生时点不同就要求复刻。客户端的内部调用顺序可以作为事实记录；只有涉及重要离散结果、可察觉差异或显著累计偏差的路径，才需要收紧项目协议。

文中分别标记客户端静态证据、原始数据引用、旧研究、项目选择和未核对事项。安装客户端的原生分支与 prefab 可以证明结构和部分顺序；没有执行 Lua 热更新或实战逐帧采样，因此不宣称完整运行版本兼容。

当前 `data/` 是整理结果，既有字段投影，也有项目假设与简化；不能仅因记录存在就认为对应机制已经还原。模板存在、关卡引用、实际可触发是三个不同的覆盖证据。

旧研究里的“已完成”也不能证明官方机制已经闭环。尤其是：controller 参数已加载不等于 Buff 已执行；支持临时路线不等于恐惧技能已支持；存在元素查询用途不等于元素损伤已实现。
