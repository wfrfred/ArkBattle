# Skill 发动变化的静态目录筛查

2026-11-17。输入为固定 `Kengxxiao/ArknightsGameData@63c7cec73c3858d0ae913f85cc89af3cef4d744f` 的完整 `skill_table.json` 和 `character_table.json`，与安装客户端分别版本化。[result.json](result.json)保留来源字节指纹、全部 SkillID 目录、关键词候选的原文／各等级参数、真实角色槽位及相关 Trait／Talent 原记录；[review.json](review.json)独立保存人工分类。

本批统计**发生了什么变化**，不以原生程序类名决定 Core 的结构，也不把能选出联合值直接当成完整 Definition 选择函数的需求。

## 分母与搜索范围

| 集合 | 数量与边界 |
| --- | --- |
| Skill 表 | 1846 个 SkillID，全部等级都搜索，不按等级重复计数。 |
| Character 表实际 `skills` 引用 | 1223 个记录关联1845个去重 SkillID；包含 TOKEN、TRAP 和不可获取角色。1842项在 Skill 表中，3项缺失，原引用保留。 |
| 可获取干员子集 | 911个去重 SkillID；只作为附加统计，没有据此排除其他记录。 |
| 未被上述 `skills` 引用的表项 | 4项为阿米娅近卫／医疗形态技能，仍搜索，不据未引用断定废弃。形态完整绑定需要其他表。 |
| 关键词候选 | 232个 SkillID、53个含相关 Trait／Talent 的角色／装置记录。各关键词集合重叠。 |
| 普通 AMMO 表项 | 39个 SkillID 的 `durationType` 为 AMMO；不是39项新的程序选择需求。 |

搜索包括次数／阶段、持续改变、自动使用、SP／魔力及充能、随机／过载／切换和相关黑板键。补入“技力需求”“所需SP”“SP消耗”“累计释放／开启”等同义表达。原正则在输出中保留，**关键词筛查不能保证语义穷尽**。模块、角色形态补丁、其他 Effect、敌人／关卡和原生 Behaviour 不是本批完整输入；既有研究中的变化不会因两张表未写明而被否定。

另以 `技能.{0,24}(?:替换|转换|改变为|更换)|(?:替换|转换|更换).{0,24}技能` 搜索全部1846项所有等级的说明，命中0个 SkillID。这只说明没有直接使用这些表达，不能证明原生不存在完整程序切换，也不能代替配置／调用链核实。

## 可确认的有限字段变化

下列10项按 SkillID 去重，不把附带的攻击效果变化另计为完整 Definition 替换：

| 类型 | 实际 SkillID | 说明及最高资料等级参数 |
| --- | --- | --- |
| 第二次起有限→无限，6项 | 青枳 S2 `skchr_buildr_2`；国度 S2 `skchr_dminon_2`；遥 S2 `skchr_haruka_2`；怒潮凛冬 S2 `skchr_headb2_2`；棘刺 S3 `skchr_thorns_3`；提丰 S2 `skchr_typhon_2` | 初次分别15／20／26／16／30／20秒，原文均明确第二次及以后无限。怒潮凛冬初次已经是 AUTO，不是触发方式切换。 |
| 第二次起有限时长变化，1项 | 薇薇安娜 S3 `skchr_vvana_3` | 15→25秒；`enhance_duration=25`。范围、连击的变化属于内容效果。 |
| 蓄力改变有限时长，2项 | 龙舌兰 S2 `skchr_takila_2`；温米 S2 `skchr_warmy_2` | 15→30秒；保留真实 `enhance_duration`／`enhanced_duration`。 |
| 蓄力改变初始弹药，1项 | 假日威龙陈 S2 `skchr_chen2_2` | 普通8发，蓄力20发；已有初始弹药输入的采样语义与之相关。 |

TIME→INFINITE 改变的是预算的联合值；时长和弹药量也有明确字段。它们尚未证明必须连带替换初始化程序、回调组、私有 State 类型或 operations 表。单位自身按次数选预算，也没有自然产生多个贡献来源的竞争需求；本批不据此决定采用 Contribution 或选择函数。

哈蒂娅 S2 的期间+15秒，以及雷狼龙S空爆两技能消耗充能后延时，另列为**已开始执行的时间操作**，不计入这10项。后者已有[Case09 §2.7](../../../cases/09-skill-mechanisms-and-requirements.md#27-原生公式复核ammosp-与具体持续时间操作)的先付首层、读取／清空剩余 SP、再延时链，不能将描述重新压成一次全额启动费用。两张表没有新增明确“同一技能按使用次数改变初始 SP 门槛／基础费用”的正例；不因此否定既有玛露西尔、Fever、Behaviour 配置更新等证据。

## 自动使用与触发枚举不是同一结论

- 重岳 S3 `skchr_chyue_3`：五次后自动释放，表仍为 MANUAL。说明能证明条件自动使用，不能单靠这句话宣布原生枚举改为 AUTO 或失去手动使用。
- 焰狐龙梓兰 S1 `skchr_orchd2_1`、丰川祥子 S1 `skchr_oblvns_1`：最大充能时自动一次；表仍为 MANUAL。应与原先的手动入口并存考虑。
- 冻河 S2 `skchr_tocka_2`：自身本来就是 AUTO，向其他干员提供临时自动使用效果。
- `trap_1516_lhnat` 供能基站、`trap_174_smfrut` 奇异黑光果实：Trait 原文另有友方自动使用政策。保留实际输入，不根据名称／前缀推断支持模式或原生精确时序。

两项表记录 `sktok_arcgacha`、`sktok_mjcsdw` 的 `skillType` 在不同资料等级间变化。这是静态配置差异，不是本批确认的运行期枚举替换。

## 程序分组与普通内容变化

人工表保留了艾雅法拉 S1、松果 S2、佩佩 S2、可露希尔 S1 的次数增益，乌有 S2 的随机效果，号角等技能的过载，以及玛露西尔 S2 只有首次允许停止。它们不能仅因出现分支就归为“替换整份 Definition”。支持 STOP 与当时允许 STOP 已是两件事；随机效果或攻击模式也可有自己所属的 Effect／Action 程序。

这里同样没有以“一个 callback 总能写 if”证明所有内容都应合并。玛露西尔 S2 的首次召唤／随后升级，结城理 S3 的形态、丰川祥子 S2 的音色，确有分组程序的理由，已单列为自然分组候选。前者还改变当前停止资格；后两者的差异主要属于持续的单位行动／Effect 程序。**本批没有取得必须在每轮更换整个 Activation 回调组、私有状态布局或操作支持表的证据**，不等于宣布所有内容都不需要这种组织。是否按独立内容 Definition 组织、再如何接入 Core，仍须比较真实调用链的清晰程度。

## 复跑

```sh
python3 docs/research/evidence/skill-activation-variation-20261117/catalog/scan.py \
  --out /tmp/skill-activation-variation-catalog.json
```

脚本仅用标准库，校验两份输入与既有固定镜像指纹一致；`--characters`、`--skills` 可指定相同字节的其他路径。`review.json` 是人工分类，不由关键词自动生成。本批不运行客户端、修改源码／测试／架构或覆盖旧研究原件。
