# 第一轮案例提炼的协议结论

这是前三案的协议归纳；第 5 节源码对照 `314b942`，不把当前有限实现视为完整官方兼容。原生事实与证据限度分别见 [Buff](01-buff-installation-and-parent-scope.md)、[行动／弹道](02-action-and-projectile-phases.md)、[派发／嵌套](03-dispatch-and-nested-settlement.md)。

## 1. 三个统一概念不足以表达行为

不能把 Buff 简化为“安装就是立即生效，结束就是 delete”；不能把攻击简化为“启动时选定目标并立即执行伤害”；也不能把结算简化为“一份最新世界加一组 hook”。

案例需要区分**身份存在、参与资格、执行进度、输入样本、派发候选及当前领域值**。它们可以出现在同一条调用链，却有不同的状态归属和可见性。

| 内容 | 归属约束 |
| --- | --- |
| 实例身份、来源与父关联、有效性、层数／余量 | 持续实例的权威事实；按所需语义表达，不复制原生字段全集 |
| 已接受行动的进度、在途绑定、缓存 ATK、已命中记录 | 可恢复的执行／投射物事实；具体容器及是否建模为 Unit 尚未决定 |
| HP、位置、当前状态与领域已登记贡献 | 相应 capability 的事实；已登记载荷与当前参与资格分别解释，有效值由本领域查询派生 |
| 有意采样的数值 | 按机制选定唯一权威归属，可属于领域贡献、附着实例或执行过程；关联与派生投影不成为第二份独立真相 |
| 光环／全局来源的接收者与接收实例绑定 | 来源过程持有的联系事实；当前几何候选只是查询结果，不自动重建这些绑定或接收实例身份 |
| 编译程序、参数读取函数、规则登记与可重建缓存 | Resources；不保存上次读到的技能状态、HP 或执行进度 |
| 同步派发候选、上下文栈、本次 Modifier 的中间值 | 本次调用上下文与领域工作值；不默认成为长期 capability 或世界副本 |

有效攻击力、防御、最大 HP、速度等查询分属相应领域；共享数值代数不意味着统一 AttributesManager 或独立 Attributes subsystem。Offense／Defense 只有静态参数时无需空 State，需要接收贡献时就持有对应领域的运行事实。Capability 的数据归属不要求它自行驱动 Effect 生命周期。

贡献不能一律解释为安装时算出的固定数，需要保留四种求值形式：固定贡献、周期／指定时点采样、状态变化时更新的维护投影、实时纯 provider。实时 provider 的程序在 Resources 中，可按调用协议读取当前事实或本次 Request／context，但保持纯查询；采样与投影更新是明确转换，不在查询时悄悄执行。

例如 Buff 层数从 2 变成 3 时，相关领域投影作为该实例转换的一部分同步更新，在任何合法后继观察前完成。暂时停止参与不统一删除或重算旧载荷，恢复不能默认重新采样。Buff 与 capability 若都能到达同一数值，必须明确哪一份权威、哪一份只是关联或受维护投影；维护投影不能成为第二份可自由修改的真相。

## 2. 可以落定的调用约束

| 协议约束 | 案例依据 | 对本项目的含义 |
| --- | --- | --- |
| 注册与生效分别解释 | 对已初始化目标，NewBuff 先登记，再执行开始动作，随后启用／进入覆盖规则；普通按 key 查询检查 enabled | 安装过程可持有实例身份，但普通规则查询不因此自动接纳该实例；不能用 collection membership 代表所有资格 |
| 停止贡献与结束完成分别解释 | MarkFinish 停用／撤贡献并向派生实例传播；ON_FINISH、容器移除与回收另有路径 | 后续查询可先失去贡献，而结束动作尚未执行；结束不能统一成为一次立即删除 |
| 来源与父作用域分别解释 | 残影绑定父天赋 Buff；源 Unit 仍在场也可能失去父作用域 | 来源事实不能代替父实例关系；父实例结束传播属于生命周期，不由 Damage 猜测 |
| 历史样本是运行事实 | 鼓舞按触发刷新保存来源值；projectile 可保存 cachedAtk | 采样后的数值属于实例／执行事实；纯属性查询不能悄悄重新采样 |
| 数值读取策略按具体参数与程序决定 | 普通弹道可在来源有效时重读 ATK，无有效来源时用缓存；另有 cachedAtkOnly 路径 | 不采用全局“攻击开始冻结全部属性”或“命中读取全部最新属性”；ATK 结论不自动推广到其他操作数 |
| 延迟命中有独立执行边界 | 能力前摇／释放与 projectile 命中通过不同路径推进 | 跨 tick 需要保存执行事实；来源失效不自动取消所有在途伤害，取消规则依具体路径确定 |
| 派发候选与参与资格分别解释 | 同一集合的活跃枚举共享候选缓存；每个候选执行前检查 ended／disabled | 候选包含当时已登记的停用实例；之后恢复可参与，新增身份不加入旧范围；嵌套调用不自动重建同集合候选 |
| 派发资格与已进入程序的后继分别解释 | 容器在取下一个 Buff 时检查有效性；动作程序按自身条件继续，也能在 FinishBuff 后运行后继 | 停止参加下一次事件不自动取消当前程序；是否继续由内容控制流与明确取消规则决定 |
| 嵌套结算返回有明确完成范围 | DamageSplit 同步调用 ApplyModifier；外层后续修改在其返回后继续 | 跨领域调用可以立即得到已生效的局部结果；不能把所有反应统一推迟到 tick 末尾 |
| HP 伤害类别与接收路径分别解释 | 分担构造无来源 PURE Modifier，并设置 SKIP_MODIFIER_EVENT 后同步接收 | 真伤不自动跳过所有接收规则；分担路径的事件参与政策需明确，不能只再次调用普通 TRUE 伤害 |
| 取消单次伤害不等于整个程序无变化 | 泥岩盾按序挡伤、回复、结束；结束后另有充能行为 | 区分领域取消、实例消耗、实际回复及内容后继；不以 hpLoss=0 统一跳过后续动作 |

Buff 核心拥有实例生命周期与有效性；接收领域定义 hook 的介入点、输入／结果、排序、允许操作和取消范围；内容程序实现登记到这些入口的行为。具体 Buff 集合的候选身份范围由本次执行上下文协调，不放进 Resources，也不由每个 Damage／Healing 请求各自重新选择一份有效列表。这个分工不增加全域 hook 总线或要求所有领域采用同一种派发政策。

这些是行为区分，不要求仿造官方类、容器或可变字段。相同可观察语义可以由不可变值转换及结构共享实现。

不要求每个简单 Effect 都执行全部阶段。没有可观察开始／结束动作的安装可以简化；没有中间观察者的贡献替换可以合并。仅当内容或嵌套查询会观察这些区别时，项目才需保留相应语义，不能因为客户端内部有字段就全部照搬。

## 3. 可见性不是一个开关

| 被读取的信息 | 需要的可见性 | 限度 |
| --- | --- | --- |
| 本次 Unit／实例事实 | 后续操作重新读取局部工作状态 | 不能继续持有嵌套调用前的可写事实副本 |
| 有效参数／状态 | 本领域查询消费当前参与的已登记贡献；已停止的贡献不再参与 | 暂停期间可以保留旧载荷；已安装但尚未启用、覆盖失效或等待刷新不是同一种情况 |
| 当前 Modifier／伤害输入 | 前一步与嵌套返回后继续处理更新后的领域值 | 不是把所有规则先汇总成一个最终倍率 |
| 派发候选身份 | 在该集合的活跃作用域中稳定 | 同一集合嵌套复用登记身份范围，含停用候选；新集合／最外层新枚举分别取输入，不冻结整个战场 |
| 每个候选的资格与实例状态 | 即将执行时重新检查当前事实 | 候选存在不代表仍可执行 |
| Buff 查询的身份范围 | UID 查询读当前登记；同集合按 key 查询复用活跃候选 | enabled 条件实时，不意味着所有普通查询的身份集合都是 live |
| Blocking／Support／导航投影 | 使用各自明确的阶段／派生版本契约 | 此轮案例没有证明它们应随每个交战步骤重建；保留现有 Blocking 阶段基线选择 |

例如，一个受击程序安装并启用新 Buff，然后递归调用同容器结算：新 Buff 可以按 UID 取得，但不进入当前共享候选，嵌套按 key 查询也沿用旧候选。反过来，旧候选被停用，即使仍在候选快照中，也应在后续执行检查时跳过；原有停用候选在轮到前恢复，则按当前资格判断。身份登记、查询候选与参与资格分别解释，不能把普通查询一概定义为 live。同步作用域必须在正常退出和异常退出时释放，不跨 tick 留在快照或 Resources 中。

## 4. 局部生效、生命周期完成、权威发布

这三者需要分别命名其含义，不要求分别成为三个 public API。

1. **局部生效**：事实与领域值成为外层后续步骤、查询或允许的嵌套结算输入。
2. **生命周期完成**：完成该对象要求的结束动作、传播、通知和移除；可以晚于贡献停止，也可能在下一次相关调用里处理。
3. **权威发布**：工作结果提交并对外公开。

官方同步可变写入只证明局部先后关系，不要求本项目在每一步公开修改 Battlefield。当前整 tick 成功后发布的规则可以保留；内部工作状态仍要体现案例中的可见性。

领域取消／拒绝不是 tick 失败：安装拒绝保留已经发生的开始动作前缀，取消伤害也不回滚回复、实例消耗或允许的后继。只有未处理异常或明确的 tick abort 才放弃整个工作结果，不发布该 tick 的事实、事件、RNG 或身份进度。纯派生缓存可以复用，但不能借此保留权威进度。

若结束／执行进度跨 tick 保留，它必须能作为事实恢复。暂停点由过程协议明确；不能把尚未完成的同步 Damage／Healing 结算只保存为外层程序计数。若候选快照与嵌套作用域只在同步调用内存在，可以由本次执行上下文持有，不进入长期 snapshot。不能把跨 tick 的权威进度伪装成 Resources 缓存。

共享当前事实与发布边界不要求一个统一 Work 类。领域可以使用窄视图、局部工作值和明确结果，但嵌套返回后的读取必须取得当前事实，不能覆盖回旧对象；Blocking／Navigation 等视图仍按自己的阶段契约解释。

## 5. 对当前实现的具体约束

| 模块 | 当前实现 | 仍需保留的边界 |
| --- | --- | --- |
| 领域资源与整局装配 | 编译函数／登记按领域分开，整局 Resources 只装配；领域贡献保存为事实，未登记某领域规则表示不参加该领域 | 程序与纯 provider 留在 Resources；实例有效性、来源过程和调用期 scope 不进入资源注册表；不追加全域 hook 槽位 |
| CombatWork 与执行 scope | Unit transition 同步接续最新事实；`EffectDispatchScope` 按接收 Unit 的活跃事件共享登记身份，并在正常／异常退出时清除 | 不冻结整个 Damage 或整份世界；每个候选轮到前检查当前参与；同容器嵌套复用候选，另一容器独立建立范围；Blocking 保留阶段基线 |
| Action program | 有序步骤、纯查询与显式 Damage／Healing operation 已能组合当前即时内容 | 跨 tick 仍需 Action-domain 可恢复执行事实与独立 projectile 过程；不用同步调用栈替代进度，也不提前固定其容器 |
| Effect lifecycle | 统一维护实例与领域 bindings；开始、参与变化、finish 和 finalize 分开；父身份独立于 source／owner，父 finish 同步传播，子 finalize 独立清理 | Status 由自身 binding 接入，通用实例无 Status 专用字段；完整覆盖／刷新、未初始化目标与非 Unit 宿主尚未完成；采样值归属按机制决定 |
| Damage／Healing hooks | 各领域拥有排序与输入／报告；hook 通过窄 facts 和明确注入的 Effect／Damage／Healing operation 组合同步嵌套 | 公式阶段只提供 Effect 操作；没有通用 Work／Battlefield mutation 权限；领域 cancellation 不自动停止剩余候选，`stopDispatch` 另行表达 |
| 已进入 callback | 活跃执行 scope 暂存当前实例最后载荷，finalize 删除 UID 前更新；callback 后继可以读取该事实 | UID／参与查询不读取这份暂存；注册已经消失，程序仍可按自身控制流继续；退出后立即清除，不进入 snapshot，也不延迟清理 |

[领域 dispatch](../../../src/core/unit/capability/vitality/damage/dispatch.ts) 捕获登记候选，排序后逐项检查当前参与和领域资格。[同容器嵌套及参与查询](../../../src/core/unit/capability/effects/dispatch.ts) 复用活跃身份范围；新增实例登记和生效仍立即进入当前工作事实，UID 查询可见。领域事件结束后调用接收者 cleanup；嵌套 cleanup 可以删除实例、运行结束动作并新建实例，而不会重建尚活跃的外层候选。

[统一 lifecycle](../../../src/core/unit/capability/effects/lifecycle.ts) 的公开安装、更新、参与变化、结束和清理都维护相应 bindings。raw 实例 primitive 只位于内部实现；内容程序通过窄 operation 访问。自动安装先执行 finished 清理，再从最新计数器分配身份，避免 ON_FINISH 嵌套安装后复用身份。安装拒绝是正常结果，保留开始动作前缀和已消费的身份进度。

[Damage](../../../src/core/unit/capability/vitality/damage/settlement.ts) 与 [Healing](../../../src/core/unit/capability/vitality/healing/settlement.ts) 返回当前工作结果和本次请求报告。当前 Damage 的确认后反应顺序为来源、目标，之后按项目致死移除契约处理；这些顺序是有限项目合同，不等于已经核对所有原生死亡／通知路径。Healing Core 用 ignoreHealFree 独立判断许可，skip 选择独立规则；已核对的原生 skip 入口由数据适配显式生成 ignoreHealFree=true，查询资格与接收资格仍分别解释。

[Offense](../../../src/core/unit/capability/offense/query.ts)、[Defense](../../../src/core/unit/capability/defense/query.ts)、[Vitality](../../../src/core/unit/capability/vitality/query.ts) 拥有各自贡献事实及当前值查询；Status 使用相同生命周期 binding 协调参与。固定／采样／维护投影不需要行为资源，实时 provider 只注入可重建的纯函数。生命周期保证状态变化与领域投影同步，但不能据此宣布所有贡献的采样和刷新政策已经确定。

## 6. 哪些仍不能统一

- 未初始化目标的首次开始动作、所有覆盖／非参与与重新参与路径尚未闭合，不能宣称所有安装都先 ON_START 再启用。
- 各攻击／命中路径的采样与取消不同；不能凭一个 cachedAtk 字段统一所有参数和攻击模式。
- 不同接收入口、事件及领域集合需要分别核对；同一 Buff 集合的枚举证据不等于所有 subsystem 全部使用同一种冻结规则。
- 实际 HP 提交、致死处理、结束通知、Unit 移除与回收不能从同步 ApplyModifier 一次性推广为同一个完成点。
- 反应之间的立即嵌套与未来 tick 执行由具体行为决定；不用全局队列或全局递归模型覆盖所有案例。

后续设计聚焦可恢复执行事实、来源过程绑定及尚未核对的领域协议。已有生命周期和局部调用上下文继续维持各自责任，不将这些过程统一包装成一个全域 Effect System。
